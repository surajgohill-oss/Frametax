# FrameTax 2.0 — Architecture

## Guiding principle

**LLMs extract. The engine calculates.**

LLMs may extract facts from scripts, budgets, PDFs, and public incentive guides.
LLMs may summarize and explain results.
LLMs may **not** perform final incentive math.
All calculations are deterministic, traceable, and testable.

## Key design decisions

### 1. UUID primary keys everywhere
All tables use `uuid.UUID` PKs generated by the application layer.
This enables record pre-generation, stable references across environments,
and avoids sequence contention.

### 2. organization_id isolation
Multi-tenant isolation is enforced at the service layer by always filtering
queries by `organization_id`. No row-level security at the DB layer in v0.1.

### 3. Confidence tiers on every rule and program
`ConfidenceTier.VERIFIED` / `PARSED` / `DISCOVERY` on every incentive rule,
program, and result. The risk-adjusted calculator applies discounts accordingly.
No rate should be promoted to VERIFIED without linking a source document.

### 4. calculation_trace_json
Every `StructureCalculationResult` stores a full trace of every arithmetic step.
This makes the engine auditable: any output number can be traced to its inputs.

### 5. LLM boundary enforcement
The `app/calculators/__init__.py` module docstring states the LLM prohibition.
Ingestion modules mark all LLM-extracted values with `is_llm_extracted=True`.
The engine never reads from LLM outputs directly — the service layer normalizes
values before passing them as plain Python types.

### 6. North America as correctness testbed
The seed migration (`0002`) covers US, Canada, and UK jurisdictions.
All seeded programs are `confidence_tier=DISCOVERY` with `base_rate=NULL`.
This is intentional — the engine must never hallucinate rates.
