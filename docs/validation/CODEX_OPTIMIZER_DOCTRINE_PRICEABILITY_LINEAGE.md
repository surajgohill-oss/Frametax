## Executive result

The 14-dimension authority-completeness framework does **not** gate the served optimizer. `canonical_evaluation.py` never imports `canonical_publication_contract.py`, `canonical_program_consolidation.py`, `authority_completeness()`, or `priceability()`. Served candidacy remains:

`jurisdiction profile -> authority_coverage_registry -> doctrine/rate presence -> production-type/minimum-QPE resolution -> allocation/QPE -> incentive -> NPC`.

The current divergence has three narrower causes:

1. The read-only publication function named `priceability()` is not runtime priceability. It reports **5 PRICEABLE / 121 UNPRICEABLE** for the 126 formulaic programs, while the served chain has **31 intrinsically priceable / 95 unavailable**. Relative to served candidacy it has 27 false negatives and one false positive (`us_ga_film_credit`).
2. The canonical served evaluator generates only the base single-country structure plus full relocations. Historically implemented split/component, hybrid/anchor, official co-production, conditional-fund, stacking, reinvestment, and in-kind mechanics survive in older calculators and the Little Utopia path but are disconnected from generic `canonical_evaluation.evaluate_project()`.
3. Authority completeness universally asks all programs for all 14 dimensions while the only two program-specific absence states, `NOT_APPLICABLE` and `AUTHORITATIVE_SILENCE_CONFIRMED`, are reserved constants that `consolidate()` never emits. This explains the current zero `AUTHORITY_COMPLETE` count, but it does not suppress pricing.

No production code, authority data, frontend, tests, or external research were changed or performed.

## Grants and funds doctrine

The retained implementation supports a type-dependent combination:

- Automatic/formula/fixed awards: deterministic NPC participation is allowed only with executable award/rate and stacking rules.
- Selective/discretionary/editorial funds: conditional opportunity, no expected value, no guaranteed NPC, and no inferred stacking.
- Fund-enabled/treaty structures: separate structure annotations/candidates when participation and membership are proven.
- Government-assistance reductions, mutually exclusive programs, allowed stacks, spend reductions, recoupment/equity terms, matching, territorial requirements and aid interactions: program-specific mechanics, never a universal grant assumption.

Current generic served implementation does none of the multi-program/fund combination work. It selects exactly one profile program per jurisdiction. That is a disconnection from the settled mechanics, not an intentional supersession.

## Official co-production doctrine

Official co-production was historically a separate candidate route, not a synonym for any multi-country split. It could unlock national treatment, domestic incentive access, specific treaty benefits, and Eurimages/Ibermedia-type funds. The three independent questions—treaty exists, the proposed ownership/contribution/cultural structure qualifies, and a domestic incentive applies—were intentionally kept separate.

Cultural qualification was therefore associated with the particular treaty/convention, national-production route, incentive, uplift, or fund that requires it. No historical evidence supports a universal `CULTURAL_OR_CONTENT_TEST` priceability requirement.

The generic current evaluator creates no co-production candidate and persists `treaty_slug=None`; the LU path auto-enumerates real treaty partners and correctly proves zero for Mauritius.

## Current served priceability chain

### Actual status path

1. `production_discovery.discover_executable_jurisdictions()` selects one `jurisdiction_comparison` profile/program per jurisdiction.
2. `authority_coverage_registry.blocks_economic_candidacy()` is consulted first.
3. A resolved doctrine exists via explicit/evidence-constrained/canonical-default inclusion.
4. At least one `RateRule` must exist.
5. `resolve_program_rate()` must match the project production type and minimum-QPE threshold.
6. `canonical_evaluation._price_candidate()` derives the QPE register, resolves the rate again against actual segment QPE, allocates accounts and calls `price_allocated_structure()`.
7. A complete, non-conditional allocation with executable segments produces `PRICED`; rank uses NPC but generic relocations remain non-comparable until relocation costs exist.

### Terminal status semantics

| Status | Exact current cause |
|---|---|
| `PRICED` | Coverage is `PRICEABLE_VALIDATED`, a rate resolves for the project, allocation is complete, and segment pricing has no blocker. |
| `UNPRICEABLE_AUTHORITY_INSUFFICIENT` | The coverage registry explicitly vetoes the program, or no executable model exists. |
| `RULE_REJECTED` | Rules exist but production type/minimum-QPE conditions do not resolve for this project. |
| `FEASIBILITY_REVIEW_REQUIRED` | Coverage disposition is selective, non-economic, superseded, duplicate, or otherwise non-priceable for a non-missing-authority reason. |
| Feasibility `STRONG/WORKABLE/WEAK/UNKNOWN` | Separate production-fit disclosure; never the economic priceability gate. |

Neither `AUTHORITY_COMPLETE == false` nor any missing all-14 field is called by this chain. Cultural test, local entity, application timing, refundability/transferability and other program requirements affect priceability only when the applicable program rule is actually encoded into a consumed condition; their mere existence as schema dimensions has no effect. Unknown territorial project facts create provisional warnings rather than a blanket rejection.

### Publication-classifier mismatch

`canonical_publication_contract.priceability()` was introduced at `770006b` as `executable_completeness()` and renamed without changing logic at `d3b893d`. It requires consolidated `PRESENT` for rate and eligible type. Consolidation only returns `PRESENT` for VERIFIED RateRules, while served `resolve_program_rate()` does not inspect confidence tier and instead relies on the independent coverage registry.

Consequences across the 126 formulaic programs:

- Served intrinsic: 31 priceable / 95 unavailable.
- Publication classifier: 5 priceable / 121 unpriceable.
- 27 served-priceable programs are publication false negatives because their executable RateRules are PARSED/DISCOVERY tier but coverage is `PRICEABLE_VALIDATED`.
- `us_ga_film_credit` is the reverse: publication PRICEABLE but served-unpriceable because the coverage registry veto is checked first.

This publication function is currently read-only and does not contaminate served economics, but its name and output are materially false as a statement of current runtime priceability.

## Fourteen-dimension contract

- Introduced at `770006b` as a read-only consolidation/residual substrate.
- `d3b893d` explicitly separated all-14 `authority_completeness()` from two-field `priceability()`.
- No committee record required every applicable program to resolve all 14 fields before pricing.
- `AUTHORITY_COMPLETE` currently asks every program for every dimension, including cap, uplift, transferability and cultural test even when a program may not have that mechanic.
- `NOT_APPLICABLE` and `AUTHORITATIVE_SILENCE_CONFIRMED` are correctly defined as researched closing states but are operationally unused: `consolidate()` explicitly never emits them.
- Result: zero authority-complete programs is partly a universal-checklist/data-publication outcome, not evidence of zero priceable programs.
- Completeness currently gates served priceability: **NO**.
- Universal-dimension assumption found: **YES, in authority completeness only**.
- First divergence location: `770006b` created a VERIFIED-tier consolidation classifier and called it executable completeness despite the served runtime using the separate coverage veto; `d3b893d` renamed the unchanged two-field result `priceability()`. The all-14 gate itself remained separate.
